주요 내용
  • 엣지(E) 2B·4B 모델이 핵심. 128K 컨텍스트, 140개 언어 지원
  • 리즈닝, 에이전트 워크플로, 펑션콜링, 코드 생성, 비전·오디오 인식 지원

  • 이미지·오디오 멀티모달: 아직 부족 (GPT-3.5 수준)
  • 4B 모델은 에뮬레이터 16GB 필요. 2B는 6~8GB
  • Gemma 3 대비 속도 압도적 개선, 한국어 문법 정확도 향상
투자/업무 시사점

MCP/CLI 없는 앱도 클로드코드로 자동화할 수 있을까?
핵심 개요

Claude의 Computer Use와 Claude-in-Chrome 기능을 활용한 업무 자동화 실전 테스트. API/MCP/CLI 없는 앱(카카오톡 등)도 AI가 직접 조작 가능한 시대 도래.

주요 내용
  • 업무 자동화 3가지 방식 정리: ①MCP/CLI(가장 안정) ②코드 스크립트(바이브코딩) ③Computer Use/Claude-in-Chrome(신규)
  • Computer Use: 데스크톱 앱 직접 조작. 스크린샷 기반으로 화면 인식→클릭→타이핑. 카카오톡 메시지 전송+파일 첨부 성공
  • Claude-in-Chrome: 크롬 브라우저 내 자동 조작. 웹사이트 UIUX 분석, X(트위터) 검색·크롤링 등 가능
  • 한계: Computer Use는 속도 느림(스크린샷 반복)+토큰 소모 큼+화면 점유로 멀티태스킹 불편. Claude-in-Chrome은 브라우저 내 작업이라 상대적으로 나음
  • 설정: Claude 데스크톱 앱에서 Computer Use/Browser Use 활성화 + 크롬 익스텐션 설치. 터미널 CLI에서도 /mcp로 연동 가능
  • 원격 조정(Dispatch) 기능과 조합 시 유의미한 유즈케이스 가능
투자/업무 시사점
  • API 미제공 서비스의 자동화 장벽 대폭 하락 → 저코드/노코드 자동화 시장 확대. 비개발자도 업무 자동화 접근 가능
  • Computer Use는 현재 Mac만 지원(리서치 프리뷰). 범용화 시 RPA 시장 구조 변화 예상
  • 토큰 소모·속도 문제 = 아직 실무 대규모 적용은 시기상조. 단순 반복 작업에 한정 적용 권장
  • Anthropic의 에이전트 역량 확장은 AI 플랫폼 경쟁에서 차별화 요소
실행 아이디어
  • 일상 반복 업무 중 API 없는 서비스(카카오톡 등) 자동화에 Claude Computer Use 시범 적용
  • 웹사이트 벤치마킹·경쟁사 분석에 Claude-in-Chrome 활용 → 크롤링 스크립트 없이 UIUX 인사이트 추출
  • 원격 조정(Dispatch) + Computer Use 조합으로 부재 시 PC 원격 자동화 구현 검토

핵심 개요

Anthropic 클로드 코드의 NPM 패키지 배포 과정에서 소스맵 파일이 포함되어 약 50만 줄 규모의 내부 TypeScript 코드가 외부에 노출된 사건 분석. 모델 가중치나 고객 데이터 유출은 아니지만, AI 업계에서 '하네스 엔지니어링'이 핵심 경쟁력이 된 시점에서 전략적으로 의미 있는 사고.

주요 내용
  • 하네스(Harness) = 모델 바깥의 실행 구조. 파일 읽기/쓰기, 터미널 명령 실행, 권한 관리, 컨텍스트 압축, 서브에이전트 위임, 백그라운드 작업 등을 결정하는 시스템. 모델이 엔진이라면 하네스는 변속기+내비+브레이크+센서 전체
  • 유출 경위: 릴리스 패키징 시 소스맵 파일이 공개 NPM 패키지에 포함 → 난독화 전 원본 구조 복원 가능. 해킹이 아닌 배포 프로세스 실수
  • 경쟁사에 미치는 영향: 클로드 코드의 Permission, Hooks, Sub-agent, Background Agent, Task 등 핵심 아키텍처 설계 철학이 노출. '잘 되는 주방의 동선과 조리 순서'가 공개된 격
  • 보안 리스크: 내부 구조 파악 → 프롬프트 인젝션 타깃 특정, 권한 체크 우회 경로 탐색, 가드레일 우회 가능성 증가
  • AI 시대 경쟁력 이동: 모델 성능(얼마나 똑똑한가) → 하네스 엔지니어링(얼마나 안전하게, 길게, 독립적으로 일하게 하는가). 에이전트 런타임 전체가 핵심 IP
